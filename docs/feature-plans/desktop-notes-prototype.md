# F11 桌面便签与晾衣线：原生交互样机

方案 v5；2026-11-16 获准调整点击展开、原位挂放与平滑过渡。正式集成已实现，状态与验证记录见 [F11 正式方案](implemented/desktop-notes.md)。样机保留为同一控制器与同一 UI 的模拟数据入口。

## 体验入口

先退出本项目现有开发实例，再执行：

```sh
npm run dev -- --desktop-notes-prototype
```

同时只运行一个本项目实例。普通 `npm run dev` 仍启动原应用。

样机直接显示一张单任务纸签、一张多任务清单和一根晾衣线。窗口默认不置顶；调整晾衣线时，左侧显示“交互样机 · 模拟任务”。任务只在内存中，单独使用系统临时目录，不读取真实任务、收入或原应用 profile；退出后不恢复本次摆位。

## 操作

- 抓住单任务顶部胶带或清单顶部纸脊拖动；靠近线显示随落点移动的吸附提示，松手保留该横向位置、仅纵向对齐绳子；不自动重排或避让。
- 纸签折起时点击纸面或夹子展开，再点夹子收回；点击另一张只展开另一张。鼠标移入或离开不改变展开状态；清单可以直接打勾。
- 抓住线上夹子向下拖，松手放到桌面。原生窗口始终固定为展开尺寸，纸面在窗口内平滑缩放、文字淡入淡出。移动超过 5 DIP 才进入拖动，松手不会误触展开；折叠纸签可直接拖走，落在桌面后展开。桌面保留最后释放位置（仅在超出屏幕工作区时校正）。
- 拖动中按 Esc 取消；快捷键占用时明确提示，可松手完成操作。
- 便签右上角按钮可直接挂起或回到上次桌面位置；夹子和折叠纸签支持 Enter / 空格展开收回。
- 线右侧提供重置和关闭；关闭会结束隔离样机，开发启动进程需在终端 Ctrl+C 停止。

## 技术边界

每张便签一个独立透明 BrowserWindow，晾衣线一个窄窗口。主进程使用 DIP 屏幕坐标进行吸附和窗口移动；以实际纸张、夹子和线上的控制区进行命中判断，空白区域通过 setIgnoreMouseEvents 穿透。只有拖动状态强制保留来源窗口输入。窗口尺寸始终不随折叠改变，纸张背景使用 transform 缩放，文本用独立图层过渡，避免已复现的原生缩放导致 pointer capture 丢失。折叠状态按可见小纸张和夹子命中，其余原生窗口透明部分穿透。松手挂入的原生窗口位置用 170ms 四次方减速过渡；拖动本身直接跟手，不做滞后缓动。

受限 preload 只开放样机命令；主进程验证来源窗口、主 frame 和本地页面地址。没有开放真实业务 IPC。显示器工作区变化时重置样机到主屏可见区域。

试验性输入门控每 16ms 检查屏幕坐标，需要用户验证快速点击、拖动、底层应用可点击与点击展开稳定性。不承诺全屏应用或跨 Space；不包含真实任务多选、清单编辑、组合拆分、持久化或完整尺寸调整。
