# F10 v3 A 可行性验证结果

日期：2026-11-05。范围：单窗口原生能力；不代表业务集成或用户体验验收通过。

## 结论

**基础窗口能力可行，严格药丸外形关卡未通过。** 现有 hiddenInset 不透明窗口可以在同一 webContents 内收缩至 240×44 DIP 并恢复，但原生窗口圆角与 22 DIP 药丸圆角不一致；CSS 药丸外仍存在可见窗口角落和点击区域。不能直接宣称已满足严格胶囊要求。

若接受系统圆角的紧凑窗口，可沿单窗口方向继续；若必须严格药丸，按 v3 停止条件先出 v4，不自动改双窗口或加原生依赖。

## 环境与证据

- macOS 26.5（25F5058e），arm64，项目锁定 Electron 45.2.2。
- 单个 2× 显示器，工作区 2560×1335 DIP（原生最大化返回高度 1336，说明系统边界须允许像素级差异）。
- main/origin/main 均为 77f94f7，fetch 后无更新；已有方案文档改动、本地 AGENTS.md 均保留。
- 探针：[scripts/probes/capsule.cjs](../../../scripts/probes/capsule.cjs)。独立临时 userData，不读取薪资、任务或正式配置，不加载正式应用代码。
- 原始原生状态：[capsule-probe-macos-results.json](capsule-probe-macos-results.json)。数据仅记录验证窗口和平台状态。
- 窗口外观及一次边角点击通过 CUA 观察，不批量截图或遍历正式业务。

## 解释边界

- 洋红色是为辨认原生窗口与内容轮廓刻意设置的对照色，不是应用主题。
- 已证伪的是“当前 hiddenInset + CSS border-radius 就等于严格药丸窗口”。没有穷尽 macOS 的全部原生实现，不应写成“macOS 完全不可能”。
- 本次未创建透明窗口；透明点击限制来自方案阶段官方资料，不能冒充本轮实测。
- 实验初次调用不存在的 getWindowButtonVisibility 导致退出；移除此探针读回项后完成验证。该项不构成产品缺陷，系统按钮改用 AX 观察；探针累计修改 2 轮。
- 正式业务数据、设置持久化、菜单草稿保护、恢复失败路径仍属于 B 阶段，不在本次通过范围。
