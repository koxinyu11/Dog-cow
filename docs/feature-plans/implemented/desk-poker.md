# 工位德州 · v6 实施记录

用户已确认 v5 修订技术与交互方案。五人无限注现金桌：玩家固定下方，电脑四席；先在独立兑换窗口以 1 狗牛币兑换 100 筹码，再选择至少 1,000 筹码入席，默认 1,000。小盲 5、大盲 10。离桌在手牌结束、结果展示完成后将全部桌上筹码返还可用筹码账户，不自动兑换狗牛币。筹码兑换狗牛币以 100 的整数倍进行，零头保留；关闭游戏与返回大厅仅暂停，本局下次继续。电脑破产后在下一手补充 1,000 筹码，玩家不会自动补充。

## 边界与维护

- `src/shared/poker/engine.ts`：纯规则、牌型评估、合法下注、分层底池、奇数筹码从庄家左侧起分配。每次行动校验筹码守恒和牌唯一。
- `src/main/poker.ts`：主进程牌序、串行行动、快照保存、请求去重、版本校验、钱包扣款/兑换及隐藏信息过滤。
- `src/main/poker/strategy.ts`：Worker 内有限采样评估（220 次）；只接收当前电脑自己的手牌与公开信息。依据个性、位置、赔率、下注压力、本桌弃牌历史和筹码压力，选择价值下注、诈唬、半诈唬或有限误判。无在线模型，无训练型最优策略；强度和自然感待体验调校。
- `src/renderer/features/playground/games/poker/`：墨绿牌桌、白色纸牌、黄铜点缀、五席布局、庄家/盲注标记、底池、当前下注与操作区。使用范围内 CSS，不影响其他游戏。
- `src/shared/poker.ts`：请求及可见视图契约。对手隐藏牌和未发牌序不提供给界面。
- 钱包新增 `poker` 账目；复用现有 Repository 原子快照、pending 确认与共享命令队列。增加 `dogcow.poker.v1` 迁移白名单；有德州资产的包必须同时含钱包，旧包缺钱包则一起保留本机钱包和德州状态。
- 游戏宿主隐藏德州的「重新开始」，不能靠重新挂载组件退款或重洗。电脑采样不占钱包队列，执行时重新校验版本。

## 错误与恢复

无效行动和过期版本拒绝执行；AI 超时/失败暂停自动推进，可重试。保存失败保留候选状态，显示上一已确认视图并锁住操作，「重试保存」只刷新磁盘，不重新下注、洗牌或结算。损坏存档保留原值，不以新局覆盖。

## 体验边界

首版荷官为轻量牌桌徽记，配合牌背洗牌、逐张公共牌揭示和筹码入场动效；不是骨骼角色动画。玩家全押后自动完成余下公共牌并结算。没有锦标赛、多人联网、抽水、自动补充玩家买入或语音对白。

规则与错误路径由业务测试覆盖；牌桌视觉、等待节奏和电脑自然程度待用户验收。非承诺穷尽所有异常。

## v3 布局修复

用户截图显示牌桌宽度塌缩，导致五席与公共牌叠在中央。大厅 `.pg-app main` 原本匹配了游戏内的 `main.pk-room`，自动外边距与无确定宽度的绝对定位牌桌形成收缩布局。改为仅匹配大厅直接子节点 `.pg-app > main`（包含窄屏规则）；德州根容器和场景明确占满可用宽度，牌桌使用 `width:100%`、`max-width:820px` 并禁止 flex 收缩。沿用原有五席与窄屏布局，不改牌局状态或钱包。技术构建及本地启动检查由 agent 执行，修复后的视觉效果待用户验收。

## v4.1 兑换、入席与结果展示

- 顶部常驻可用筹码与「兑换」入口。原生 dialog 提供双向兑换、源余额、数量、到账预览与快捷金额；打开时暂停后续电脑行动和结算展示。保存失败保留输入并提供重试。
- `exchangeCoins` / `exchangeChips` 只兑换可用余额；`join` 只扣筹码，不扣狗牛币。`reserve` 从零头扩展为可用筹码账户，原 v1 存档与原桌上筹码兼容，无重新收费。
- 本手结果持久化 `settlement`：按层记录主池、边池、未被跟注退款的 recipients / amount，保存发放前余额、总所得、摊牌赢家的最佳五张牌。非摊牌获胜不暴露隐藏牌。
- `useSettlement.ts` 仅维护展示游标：公共牌揭示后，按池高亮与推筹码，逐批增加显示余额并显示所得；结束后开放下一手或离桌。可跳过，支持减少动态效果；重新进入只重播结果，不触发资金操作。旧的已结束牌局缺少结果元数据时显示旧的最终结果，不伪造分池过程。
- `Chips.tsx` 是下注、底池、推筹码、兑换图例共用的筹码呈现。白 1 / 红 5 / 蓝 10 / 绿 25 / 黑 100 / 紫 500，带切口、面额、有限堆叠，精确数字单独显示。
- 用户提前选择「本手后离桌」时，后台保留已完成牌局供动画展示；动画结束再提交离桌请求。离桌回执保存本次带入、带出及差额，新入席后重置。
- 业务测试覆盖两向兑换边界、重复请求、旧存档、入席只扣筹码、离桌只返还筹码、真实快照失败恢复，以及分池/平局/退款结果明细；视觉与动效节奏待用户验收。

## v5 入席主页、净赢庆祝与策略

- 用户明确范围：窗口内适配仅针对德州入席主页，牌桌排布不改。主页左右分区，左侧标题、盲注及上局结果，右侧金额输入、快捷金额、入席按钮；可用筹码与兑换入口各仅保留顶部一处。低高度容器收起装饰牌，保留所有操作和必要信息。
- 前后端最低入席筹码统一 1,000，快捷金额为 1,000 / 2,000 / 5,000。仍允许旧桌以不足 1,000 的现有筹码继续，无补扣。
- `settlement.netGains` 记录每席所得减去本手投入。玩家净赢 > 0 时，在分池完成后播放约 1.6 秒的金币/六色筹码洒落；装饰限定在牌桌场景内，无指针拦截；跳过同时终止结算与庆祝，暂停冻结动效，减少动态效果时略过。旧结果缺少净赢元数据则不补算或伪造庆祝。
- 引擎新增可选 `actions` 公开结构化记录（座位、轮次、行动、付出、下注额、行动前底池），最多 120 条；`reads` 保存本桌各席弃牌/加注/跟注频率并跨手继承。旧桌无字段时按空记录处理。
- Worker 在有限提案中按公开行动加权抽样手牌范围；按当时已公开的公共牌计算范围权重，未知真实手牌和未发牌序不参与。翻牌前 320 次、翻牌后 440 次抽样；结合赔率、位置、有效筹码、湿润牌面、公开弃牌倾向、人物偏好和有限误判选择动作、下注尺寸。属于近似娱乐策略，非 GTO 保证。
- 技术检查：构建及 79 项相关业务测试通过，包含公开记录、加注范围权重、固定随机种子的合法行动、隐藏牌独立性、坚果牌不弃、最低买入与旧桌兼容、净赢判定。
- 未验证边界：新增 `scripts/test-poker-entry.mjs` 使用模拟数据和隐藏 Electron 窗口检查 720×520 / 960×680 元素边界，不读取用户数据、不截图；本机临时 file 页面加载连续三次超时，未取得几何断言结果。已尝试独立临时 profile、禁用 GPU 与关闭后台节流，仍停在页面加载；停止重试。故主页窗口适配与撒钱动效仍待用户验收，不能以构建通过替代。

## v6 四项 review 修复

- 兑换：`PokerExchangeClient` 在 localStorage 写入单笔 outbox 后才发送。原请求号、方向、数量、创建时间跨游戏重新挂载保留；不确定结果先通过主进程 `exchangeStatus` 查询，已完成只同步余额，未完成重试原编号，待保存则先重试磁盘保存再核对。界面未核对前禁用新兑换与修改输入。明确业务拒绝也先查询确认未执行，再解锁修改输入。
- 主进程在同一快照持久化最多 128 个兑换回执，并检查重放参数；回执淘汰时保存 `exchangeFloor`，超过 24 小时或落在淘汰水位之前的未知请求不会重新执行。过期记录在刷新余额后由用户明确结束，不能静默重发。localStorage 写入失败不发送扣款命令。
- 诈唬：将不可达的 `!wet` 改为明确的干燥牌面阈值，提取共享的 `bluffOpportunity`；覆盖真实河牌决策中成功/失败的诈唬概率分支，不只测试布尔条件。
- 合法动作：加注必须仍有另一位未弃牌、持有可投入筹码的对手；全员全押后的跟注不再允许制造无意义退款。
- 校验：`src/migration/poker.js` 是状态加载、备份导入与引擎断言共用的无副作用验证器，检查五席、牌范围/唯一性/含烧牌的张数、轮次/行动者、筹码守恒、公开记录、统计、回执以及结算分配/金额/牌归属。旧桌可缺 actions、reads、settlement、netGains 与新回执字段；异常数据抛错并保持原值，不生成新局覆盖。
- 验证：构建与 90 项相关回归测试通过。首次河牌用例误用了 A-2-3 连张风险牌面，调整为干燥牌面后通过；未调整算法去迎合错误牌面。第二轮 review 覆盖 outbox 与服务端回执、保存确认、过期/淘汰处理、业务拒绝恢复、旧存档及共用校验入口。
- 既有边界：主页几何检查仍受隔离页面加载超时影响，本轮不重试或声称通过；界面操作体验与布局待用户验收。未提交、push 或发布。
