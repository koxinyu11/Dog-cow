# Mac 安装更新（F02，自 v3.1.0 起发布）

方案 v2 及修复 v2.2、v2.3、v2.4 已批准；已随 v3.1.0 发布，未对用户正式安装执行更新。已修正 lipo 参数、preload 白名单、助手自身 PID 误判和嵌套目录备份。该功能开发阶段通过类型检查、478 项测试及 Mac 测试包构建；v3.1.0 发布构建通过 507 项测试及完整打包。

真实打包隔离验收通过：将仅测试应用从 3.0.5 升级到 3.0.6，使用独立 profile。数据备份位于实际的 profile/updates/install-job-*/data-backup 中，旧测试应用通过 Cmd+Q 正常退出，独立助手完成替换，新版显示原任务、备注及 37% 进度，并写回 ready.json；任务状态 completed，旧应用备份仍在，升级后的应用签名校验通过。两个测试实例均已正常退出。该验证未操作用户正式安装或正式数据。

## 入口和责任

- `release-updates.ts`：原有 GitHub 来源限制、大小及 SHA-256 校验；增加准备、安装状态，安装中暂停新的下载检查。
- `update-install.ts`：只读挂载 DMG、准备相邻暂存应用，复制独立助手，等待助手就绪。
- `update-helper.ts`：仅依赖 Node 内置模块。构建时复制为 `Contents/Resources/update-helper.mjs`。通过随应用分发的 Electron 的 Node 模式执行，无需系统安装 Node。
- `main.ts`：仅已安装 Mac 正式版开放一键安装；草稿、仓库和窗口状态必须保存成功，然后备份数据并正常退出。保存失败不允许放弃修改继续安装。
- DMG 的 `安装或替换狗牛.command`：调用同一助手安装到 `/Applications/狗牛.app`，目标正在运行则停止，请用户正常退出。原有拖拽安装保留。

应用内支持 `/Applications/狗牛.app` 和 `~/Applications/狗牛.app`。开发实例不下载、不执行正式版安装。首个包含本功能的版本仍需通过 DMG 入口升级。

## 替换和恢复

准备阶段校验 Bundle ID、版本、架构、签名和目标路径，拒绝符号链接目标及降级；新版复制到目标同一目录下的隐藏暂存路径，校验后才退出旧应用。无管理员提权、不发送 kill、不清除隔离标记、不修改 Gatekeeper。

每次安装使用 0700 的 `install-job-*` 目录，包含受限清单、状态、独立助手及数据备份。旧版改名为同目录 `.dogcow-old-<id>.app` 后，新版改名进入目标。两次重命名不是整体原子操作：状态在移动前落盘；助手失败时恢复旧版，下次启动或 DMG 安装入口只恢复“目标缺失、旧备份存在”的中断状态，不覆盖已存在的新应用。

新版加载后核对目标、版本和任务标识，写入就绪确认。未收到确认不自动回滚用户数据；保留应用和备份，提供诊断。下一次成功更新可清理前一次已完成任务的旧应用备份；失败任务与数据备份保留供恢复。手动安装脚本会显示恢复目录。

应用内备份位于当前 profile 的 `updates/install-job-*/data-backup`；手动入口的数据备份位于系统临时目录的 `dogcow-data-backup-*`。备份排除 updates，避免递归复制安装缓存。长期保存请另行导出备份，不依赖系统临时目录。

## 验证与限制

隔离测试只操作系统临时目录内的测试应用，使用 clang 生成小型 Mach-O 并临时签名，不退出、替换或改写任何正式版数据。覆盖替换确认、复制数据、替换失败恢复、目标运行、取消、未确认启动、重命名中断、版本和符号链接拒绝。

单元测试中的启动确认使用注入钩子；另已在真实 Electron 打包隔离副本中验证独立助手、正常退出、替换和新版就绪确认。为保证隔离，仅在测试副本中固定独立 profile 并延迟自动更新检查，没有修改交付代码的安装目标限制。正式安装内点击“安装并重启”的端到端操作未执行；DMG 脚本固定指向 /Applications，未在用户机器上执行替换入口。Developer ID 签名、公证及新 Mac 的 Gatekeeper 放行未验证，仍可能出现系统安全提示。

## 维护性检查

备份范围仍为整个 profile 除 updates，仅将 Node 不支持的“整目录复制到子目录”改为逐项复制。两个安装入口共用同一助手；进程识别按 PID 和可执行路径排除自身，不扩大到按应用名关闭进程。未引入新依赖或常驻服务。本任务外的带薪活动改动保持独立；本功能自 v3.1.0 起发布。
